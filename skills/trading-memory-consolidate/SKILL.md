# OpenCode 执行边界

1. Vault、MEMORY.md、交接文件和交易记忆目录只读。
2. 禁止自动创建、修改、移动、删除、回写或归档任何 Vault 文件。
3. 默认输出到 `{OPENCODE_CONFIG_ROOT}\outputs\trading\memory\consolidation\`。
4. 只生成审阅结果、总表草稿、迁移计划和校验报告；不执行实际迁移。
5. 不调用 MiMo、DSH、Obsidian、domain-memory 或 Git 推送工具。
6. 不访问账户、凭据或实时网络；所有事实必须来自用户明确提供或允许读取的本地文件。

# 交易记忆归纳整理工作流

## 触发方式

- 用户明确说“整理记忆”“归纳记忆”“记忆总表”“审阅记忆”或 `consolidate memory` 时执行。
- 默认只做全量或用户指定范围的只读审阅。
- 用户确认输出目录后才创建 OpenCode 非 Vault 草稿文件。

## 方法论五问

在开始扫描前，向用户确认以下问题；如果用户已经明确回答，不重复提问：

1. 交易记忆在体系中的作用是什么？
2. 当前整理想法是否存在把演化误判为冲突的风险？
3. 使用什么决策场景维度组织总表？
4. 否决案例和执行绩效是否进入总表？
5. 哪些内容属于永久规则、模式层或易变快照层？

推荐默认：永久规则、模式层和快照层分层；否决案例和亏损绩效必须保留；按决策场景而不是日期组织。

## 输入

读取用户明确指定的范围：

- 交易记忆 Markdown 文件；
- 交易记忆总表；
- 最近复盘文件；
- 交接文件；
- 用户提供的冻结状态或规则说明。

输入缺失时列出文件清单和缺失原因，停止生成总表，不创建占位记忆。

## 第一步：批量清点

使用 `glob` 和 `read` 读取所有目标文件，按文件名、日期、主题、类型、来源和 frontmatter 建立清单。记录：

- 文件路径；
- 文件类型；
- 创建或更新时间；
- 预测与假设；
- 实际结果；
- 偏差分析；
- 规则；
- 置信度；
- 关联复盘和案例。

长文件必须逐篇清点，不能只依赖截断输出。

## 第二步：冲突归因

每处不一致必须归入以下一类：

- 演化：旧规则被新规则替代，保留演化链；
- 真冲突：同一时间口径下互相矛盾；
- 互补：不同维度描述不同事实；
- 事实错误：历史记录本身错误；
- 覆盖缺口：复盘有重要裁决但没有对应记忆。

同时统一统计口径。记忆是历史先验，不是当前市场裁决标准；新证据优先进入待审草稿，不自动覆盖旧记录。

## 第三步：生成总表草稿

总表草稿写入 OpenCode 非 Vault 输出目录，包含八个区域：

- A：量能与判据；
- B：模式识别；
- C：纪律铁律；
- D：案例库；
- E：标的演化链；
- F：纠错记录；
- G：覆盖缺口；
- H：冻结状态速查。

每条规则必须包含：

- 规则正文；
- 实证次数；
- 最近验证日期；
- 当前状态；
- 来源文件；
- 是否需要人工裁决。

易变资产价格、短期状态和临时快照不进入永久规则区。

## 第四步：生成迁移计划

只生成计划，不执行移动或写入。计划至少包含：

- 原始文件到目标分类的映射；
- 演化关系；
- 需要合并的互补条目；
- 需要人工裁决的真冲突；
- 不得移动的原始证据文件；
- 建议保留的版本链；
- 后续需要用户授权的操作。

## 输出文件

默认目录：`{OPENCODE_CONFIG_ROOT}\outputs\trading\memory\consolidation\`

可生成：

- `YYYY-MM-DD-审阅清单.md`；
- `YYYY-MM-DD-记忆总表草稿.md`；
- `YYYY-MM-DD-迁移计划.md`；
- `YYYY-MM-DD-质量检查.md`。

文件名和日期由用户确认；没有明确输出目录时只在对话中展示。

## 质量检查

- 每篇输入都已列入清单；
- 每处冲突都有归因；
- 演化链保留旧版本；
- 否决案例和执行绩效没有遗漏；
- 快照层没有进入永久规则；
- 草稿没有声称已经写入 Vault；
- 所有需要人工裁决的项目已单独列出。

## 边界

- 不删除原始记忆；
- 不移动原始记忆；
- 不修改 MEMORY.md 或交接文件；
- 不更新交易记忆总表；
- 不推送 Git；
- 不自动运行全 vault 扫描以外的副作用操作。
