## OpenCode 双端执行约定

本文中的 `powershell` 代码块是 Windows 示例；macOS 使用 `bash`/`zsh`。统一先设置 `SKILL_ROOT` 和 `PY`：Windows 使用 `$env:USERPROFILE\.config\opencode\skills\<skill>` 与 `python`，macOS 使用 `$HOME/.config/opencode/skills/<skill>` 与 `python3`。优先使用 `runtime-preflight`、`safe-output` 和 `market-data` 工具；不要把示例中的路径直接复制到另一端。输出必须位于本机 OpenCode 输出根，Vault 默认只读。

# OpenCode 执行边界

1. Vault 文件只读；禁止创建、修改、移动、删除、回写或归档任何 Vault 文件。
2. 默认结果写入 `{OPENCODE_CONFIG_ROOT}\outputs\trading\daily-review\`；用户要求只在对话展示时不创建文件。
3. 交易计划、记忆文件和复盘文件只读；任何计划或记忆写入必须另行获得用户明确授权，并使用非 Vault 路径。
4. 盘前、盘中、盘后流程均由用户手动触发，不创建系统定时任务，不发送外部通知。
5. 公开网络只在用户实际触发且当前阶段需要行情或新闻时访问；不访问账户、Cookie、Token 或交易凭据。
6. 不调用 MiMo、DSH、Obsidian、domain-memory 或 Excel 专用工具。
7. 任何输入缺失都必须显式列出，不创建占位文件，不猜测数据。

# 每日复盘工作流

## 触发方式

- 用户明确说“盘前复盘”“盘中验证”“盘后复盘”“制定观察清单”或“审查交易计划”时执行。
- 不在后台自动运行，不补跑错过的时点。
- 每个阶段只使用已经存在且用户允许读取的输入。

## 输出位置

- 默认报告：`{OPENCODE_CONFIG_ROOT}\outputs\trading\daily-review\YYYY-MM-DD-{阶段}.md`。
- 默认记忆提炼：写入 `{OPENCODE_CONFIG_ROOT}\outputs\trading\memory\`。
- 用户指定其他非 Vault 路径时，使用用户指定路径。
- 任何路径若无法证明不在 Vault 内，停止写入并在对话中报告。

## 时间与输入

每个阶段开始先确认当前日期、时间和交易阶段。输入包括：

- 前两个交易日复盘；
- 当日财经早读；
- 盘前预测和观察清单；
- 交易计划与当前持仓；
- 交易记忆总表；
- 用户明确提供的数据文件。

缺少关键输入时，列出缺失项并停止当前阶段。历史文件只读，不为补齐结构而创建文件。

## 数据获取

### 公开行情入口

使用 OpenCode 自带 Node 入口：

```powershell
$MK = "$env:USERPROFILE\.config\opencode\skills\_shared\opencode-market.mjs"
node "$MK" index
node "$MK" stocks "1.600000,0.000001"
node "$MK" sector 20
node "$MK" sina "sh600519,sz000001"
node "$MK" tencent "sh600519,sz000001"
node "$MK" kline "SH600519" 101 120
node "$MK" get "<公开页面 URL>"
```

- 东方财富数据作为成交额和指数口径基准。
- 新浪和腾讯用于交叉复核。
- `opencode-xueqiu.mjs` 仅在用户明确允许且网络可达时作为可选第四源；失败不影响主链。
- 多源冲突必须显著标注，不自动选择未说明的来源。
- 期货字段必须确认输出含 `kind` 字段；无法确认时只报告原始来源，不做期货实时结论。

### 新闻和公告

- 使用当前会话的 `webfetch` 或 `websearch`，仅访问公开页面。
- 新闻、公告和研报必须记录 URL、来源和采集时间。
- 无法访问时保留 `[待补]`，不以常识替代事实。

## 阶段一：盘前准备

1. 读取最近两个有效交易日复盘，提取明日关注点和可验证假设。
2. 读取当日财经早读；不存在时记录缺失。
3. 读取状态为等待入场或持仓中的交易计划，检查入场条件、前提及失效条件。
4. 读取用户提供的商品锚映射，核验对应公开行情。
5. 读取交易记忆总表，提取与当日场景相关的规则和实证次数。
6. 在 OpenCode 输出中生成盘前观察清单，包含市场量能、板块龙头、科技分化、商品锚和需要人工决策的事项。
7. 不创建或修改任何交易计划；需要新建计划时先向用户确认。

## 阶段二：盘中验证

盘中验证由用户在对应时点手动触发，推荐三个窗口：

- 10:00 至 10:30：量能推算、指数、板块和商品锚；
- 13:00 至 13:30：检查反转和假设变化；
- 14:30 至 14:45：检查收盘确认条件。

每个窗口执行：

1. 拉取指数、观察标的、板块资金和必要的商品行情。
2. 对照盘前观察清单逐项验证。
3. 对触发位或重大异动复验商品锚和公开新闻。
4. 对照交易计划，但只提醒，不执行交易、不修改计划。
5. 将结果写入 OpenCode 非 Vault 盘中记录；不写入前日复盘或任何 Vault 文件。

盘中结果必须包含数据时间、来源、实际值、与假设的差异和需要用户决策的事项。

## 阶段三：盘后复盘

1. 确认当前日期和交易日。
2. 读取当日完整数据、盘中记录、前两个交易日复盘、交易计划和记忆总表。
3. 调用 `trading-contradiction-check` 的逻辑，检查预判、板块、持仓逻辑和量能一致性。
4. 审查交易计划的前提和失效条件，只输出审查意见。
5. 生成 OpenCode 盘后复盘，包含数据来源、数据级别、事实、判断、假设、矛盾检测和待人工决策项。
6. 不更新前日复盘、不创建 Vault 复盘、不移动历史文件。

## 记忆提炼

盘后只生成“记忆候选”，不直接写入 Vault 或交易记忆库。

每条候选必须包含：

- 预测或假设；
- 实际结果；
- 偏差分析；
- 可沉淀规则；
- 置信度；
- 来源复盘和日期。

默认写入 `{OPENCODE_CONFIG_ROOT}\outputs\trading\memory\`。是否合并到交易记忆总表由用户另行授权和触发 `trading-memory-consolidate`。

## 观察清单结构

```text
第一层：市场整体量能
第二层：板块龙头量能验证
第三层：科技分化信号
第四层：持仓商品锚核验
决策树：量能达标且方向确认则进入规则，否则观望或防守
```

## 盘后报告结构

```markdown
# YYYY-MM-DD 盘后复盘

## 数据范围与来源
## 核心摘要
## 一、大盘与量能
## 二、资金动向
## 三、板块表现
## 四、核心驱动
## 五、与前日复盘的连贯性
## 六、明日关注点
## 七、交易计划审查
## 八、可验证假设
## 九、矛盾检测
## 十、记忆候选
## 十一、需人工决策
```

## 交易计划与记忆边界

- 复盘只分析市场，不替用户创建、修改或执行交易计划。
- 交易计划审查只输出前提、触发距离和失效条件。
- 记忆总表只读；记忆候选默认写入 OpenCode 非 Vault 目录。
- 任何写入 Vault 的计划、复盘、记忆或归档操作都必须得到用户对该次操作的明确授权。

## 失败处理

- 行情接口失败一次后停止重试，保留 `[待补]` 和错误来源。
- 不用其他数据源悄悄替代失败源；如需替代必须显式说明口径变化。
- 缺少复盘或计划文件时停止相关审查，不自行补造历史。
- 任何异常都写入 OpenCode 复盘记录，不写入 Vault。
