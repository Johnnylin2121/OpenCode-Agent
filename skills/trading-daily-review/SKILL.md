# OpenCode 执行边界

1. Vault 文件只读；禁止创建、修改、移动、删除、回写或归档任何 Vault 文件。
2. 默认结果写入 `{OPENCODE_OUTPUT_ROOT}/trading/daily-review/`；用户要求只在对话展示时不创建文件。
3. 交易计划、记忆文件和复盘文件只读；任何计划或记忆写入必须另行获得用户明确授权，并使用非 Vault 路径。
4. 盘前、盘中、盘后流程均由用户手动触发，不创建系统定时任务，不发送外部通知。
5. 公开网络只在用户实际触发且当前阶段需要行情或新闻时访问；不访问账户、Cookie、Token 或交易凭据。
6. 不使用其他 Agent 专用工具、Obsidian 插件、外部记忆插件或 Excel 商业插件；行情统一走下方 OpenCode 入口。
7. 任何输入缺失都必须显式列出，不创建占位文件，不猜测数据。

# 每日复盘工作流

## 触发方式

- 用户明确说“盘前复盘”“盘中验证”“盘后复盘”“制定观察清单”或“审查交易计划”时执行。
- 不在后台自动运行，不补跑错过的时点。
- 每个阶段只使用已经存在且用户允许读取的输入。

## 输出位置

- 默认报告：`{OPENCODE_OUTPUT_ROOT}/trading/daily-review/YYYY-MM-DD-{阶段}.md`。
- 默认记忆提炼：写入 `{OPENCODE_OUTPUT_ROOT}/trading/memory/`。
- 用户指定其他非 Vault 路径时，使用用户指定路径。
- 任何路径若无法证明不在 Vault 内，停止写入并在对话中报告。

## 时间与输入

每个阶段开始先确认当前日期、时间和交易阶段。Vault 路径一律以 `交易体系/` 下的**编号目录**为准（09-28 重组后已带前缀，2026-09-29 实测校正）。输入包括：

- 前两个交易日复盘 —— `交易体系/06.每日复盘/`（更早已归档至 `交易体系/_归档/每日复盘/`）
- 当日财经早读 —— `交易体系/01.财经早读/`（更早已归档至 `交易体系/_归档/早读/`）
- 盘前预测 —— `交易体系/04.盘前预测/`；盘中验证 —— `交易体系/05.盘中验证/`（归档分别在 `_归档/盘前预测/`、`_归档/盘中验证/`）
- 交易计划与当前持仓 —— `交易体系/03.交易计划/`
- 交易记忆总表 —— `交易体系/07.交易记忆/00-交易记忆总表.md`（原文件在 `_归档/交易记忆/`）
- 早读复核（可选输入） —— `交易体系/09.新闻资讯/早读复核/`
- 纪律与策略 —— `交易体系/02.交易策略/`
- 跨域引用可读 `wiki/`（交易）、`wiki-work/`（工作）、`wiki-reading/`（读书）三域
- 用户明确提供的数据文件。

缺少关键输入时，列出缺失项并停止当前阶段。历史文件只读，不为补齐结构而创建文件。

## 数据获取

### 公开行情入口

使用 OpenCode 自带 Node 入口：

```powershell
$MK = "$env:USERPROFILE\.config\opencode\skills\_shared\opencode-market.mjs"
node "$MK" index
node "$MK" stocks "1.600000,0.000001"
node "$MK" sector 20
node "$MK" sina "sh600519,sz000001"
node "$MK" tencent "sh600519,sz000001"
node "$MK" kline "SH600519" 101 120
node "$MK" get "<公开页面 URL>"
```

macOS 对应写法：`$MK="$HOME/.config/opencode/skills/_shared/opencode-market.mjs"`，其余子命令一致。也可直接使用 OpenCode 内置 `market-data` 工具（`index`、`stocks`、`sina`、`tencent`、`kline`、`sector`、`get`）。

- 东方财富数据作为成交额和指数口径基准。
- 新浪和腾讯用于交叉复核。
- `opencode-xueqiu.mjs` 仅在用户明确允许且网络可达时作为可选第四源；失败不影响主链。
- 多源冲突必须显著标注，不自动选择未说明的来源。
- 期货字段必须确认输出含 `kind` 字段；无法确认时只报告原始来源，不做期货实时结论。

### 新闻和公告

- 使用当前会话的 `webfetch` 或 `websearch`，仅访问公开页面。
- 新闻、公告和研报必须记录 URL、来源和采集时间。
- 无法访问时保留 `[待补]`，不以常识替代事实。

## 阶段一：盘前准备

1. 读取最近两个有效交易日复盘（`交易体系/06.每日复盘/`），提取明日关注点和可验证假设。
2. 读取当日财经早读（`交易体系/01.财经早读/`）；不存在时记录缺失。
3. 读取 `交易体系/03.交易计划/` 下状态为等待入场或持仓中的计划，检查入场条件、前提及失效条件。
4. 读取用户提供的商品锚映射，核验对应公开行情。
5. 读取交易记忆总表（`交易体系/07.交易记忆/00-交易记忆总表.md`），提取与当日场景相关的规则和实证次数。
6. 在 OpenCode 输出中生成盘前观察清单，包含市场量能、板块龙头、科技分化、商品锚和需要人工决策的事项。
7. 不创建或修改任何交易计划；需要新建计划时先向用户确认。

## 阶段二：盘中验证

盘中验证由用户在对应时点手动触发，推荐三个窗口：

- 10:00 至 10:30：量能推算、指数、板块和商品锚；
- 13:00 至 13:30：检查反转和假设变化；
- 14:30 至 14:45：检查收盘确认条件。

每个窗口执行：

1. 拉取指数、观察标的、板块资金和必要的商品行情。
2. 对照盘前观察清单逐项验证。
3. 对触发位或重大异动复验商品锚和公开新闻。
4. 对照交易计划，但只提醒，不执行交易、不修改计划。
5. 将结果写入 OpenCode 非 Vault 盘中记录；不写入前日复盘或任何 Vault 文件。

盘中结果必须包含数据时间、来源、实际值、与假设的差异和需要用户决策的事项。

## 阶段三：盘后复盘

1. 确认当前日期和交易日。
2. 读取当日完整数据、盘中记录、前两个交易日复盘、交易计划和记忆总表。
3. 调用 `trading-contradiction-check` 的逻辑，检查预判、板块、持仓逻辑和量能一致性。
4. 审查交易计划的前提和失效条件，只输出审查意见。
5. 执行**盘后第 4.5 步：全面更新交易计划文件**（见下节，常态化步骤，不得跳过）。
6. 执行记忆提炼，产出记忆候选。
7. 生成 OpenCode 盘后复盘，包含数据来源、数据级别、事实、判断、假设、矛盾检测、交易计划更新提案和待人工决策项。
8. 不更新前日复盘、不创建 Vault 复盘、不移动历史文件。

## 盘后第 4.5 步：全面更新交易计划文件（常态化，2026-09-29 立）

> 规则：盘后复盘完成即进入本步，**不得跳过**。
> 来源：用户 2026-09-29 指令「复盘后全面更新交易计划文件这个要常态化」。与 DSH 侧同名步骤口径一致，但执行方式按 OpenCode 只读边界适配。

### 范围

逐一审查 `{VAULT_PATH}/交易体系/03.交易计划/` 下**全部**文件，按当日收盘实际情况逐项判定：

| 文件 | 更新内容 |
|------|----------|
| `00-交易体系待解决清单.md` | 状态快照滚动至当日；新增或结项待裁决项 |
| `持仓操作预案-*.md` | 判定结果、条款距离、口径变更（如收盘 ↔ 尾盘） |
| `当前持仓.md` | 滚动至当日收盘：价格、浮盈亏、占比、距防线距离 |
| `南山铝业-除权参数切换预案.md` | 窗口日计数、参数激活状态、口径变更 |
| `银行股息率月度评估.md` | 非月度更新日也追加检查记录（股息率是否仍 ≥ 门槛） |
| 其他文件 | 按需更新；新建计划须经用户确认 |

### OpenCode 边界

1. **默认只读**：Vault 交易计划文件只读。本步默认产出「更新提案」，不直接写回。
2. 提案写入 `{OPENCODE_OUTPUT_ROOT}/trading/plan-refresh/YYYY-MM-DD-<文件名>.md`，逐文件给出：现值 / 建议新值 / 依据数据源与时点 / 影响的执行条款。
3. **仅当用户对该次写回明确授权**时，才按提案更新 Vault 文件；每个文件须追加 `[agent: OpenCode | <ISO 8601 带时区>]` 签名。
4. 任何 Vault 写回必须在 `_系统/日志/log.md` 追加七字段审计（写入者 / 写入时间 / 操作 / 目标 / 摘要 / 来源依据 / 验证），写入者只能填 `OpenCode`。
5. 不删除、不移动、不重命名交易计划文件；失效计划改状态标注，不删文件。
6. 更新前必须先读该文件当前内容（云同步会刷新 mtime，不读就写等于覆盖他人成果）。
7. 每条数据标注来源与时点；跨来源冲突显式写出口径提示；缺数据写「待补」，不猜测、不用「大概率」填补。

## 记忆提炼

盘后只生成“记忆候选”，不直接写入 Vault 或交易记忆库。

每条候选必须包含：

- 预测或假设；
- 实际结果；
- 偏差分析；
- 可沉淀规则；
- 置信度；
- 来源复盘和日期。

默认写入 `{OPENCODE_OUTPUT_ROOT}/trading/memory/`。是否合并到交易记忆总表由用户另行授权和触发 `trading-memory-consolidate`。

## 交易计划与记忆边界

- 复盘只分析市场，不替用户创建、修改或执行交易计划。
- 交易计划审查只输出前提、触发距离和失效条件。
- **盘后必须执行「全面更新交易计划文件」（第 4.5 步，常态化）**——默认产出更新提案；Vault 写回需用户对该次操作明确授权，并强制写 `_系统/日志/log.md` 审计。
- 记忆总表只读；记忆候选默认写入 OpenCode 非 Vault 目录。
- 任何写入 Vault 的计划、复盘、记忆或归档操作都必须得到用户对该次操作的明确授权。

## 失败处理

- 行情接口失败一次后停止重试，保留 `[待补]` 和错误来源。
- 不用其他数据源悄悄替代失败源；如需替代必须显式说明口径变化。
- 缺少复盘或计划文件时停止相关审查，不自行补造历史。
- 任何异常都写入 OpenCode 复盘记录，不写入 Vault。
